# Skill 01: COMSOL Model Intake and Scope Discovery

## Purpose

COMSOLファイル、exportフォルダ、または既存caseを受け取った最初の段階で、比較可能性を判断する。ここでモデル構造を誤認すると、後続の抽出・実行・評価がすべて誤る。

## Inputs

Possible inputs:

```text
.mph file
.mphtxt mesh export
COMSOL-exported CSV / TXT tables
field NPZ bundle
existing run_config.yaml
particle long trajectory CSV
release CSV
wall/boundary map CSV
```

## Steps

### 1. Inventory all available assets

Create `extraction_manifest.yaml` from the template. Record:

- file paths
- file sizes
- modified times if useful
- expected role
- whether the file is raw COMSOL, derived export, solver input, or solver output

### 2. Identify model scope

Do not assume these. Inspect or request them:

- COMSOL version
- component name
- geometry dimension: 2D, 2D axisymmetric, 3D
- coordinate names and units
- study type: stationary, time dependent, parametric
- dataset/solution used for field export
- particle tracing interface present or absent
- release features present or absent
- wall/boundary features present or absent
- stochastic physics present or absent

### 3. Choose comparison mode

Use `comsol_faithful` when:

- comparing against COMSOL particle tracing output
- COMSOL release table and particle trajectories are available
- you need machine comparison of release, field, force, wall, and trajectory

Use `surface_release_production` when:

- COMSOL is only a source of stationary fields/geometry
- particles are generated by this code from part surfaces
- boundary release preprocessing is intentional

Do not mix these modes in one run.

### 4. Create an intake summary

Write `comsol_intake_summary.md` with:

```text
available assets
missing assets
model dimension and coordinate system
selected component/study/dataset
available fields
available particle references
comparison mode recommendation
stop conditions
next skill to run
```

## Required outputs

```text
extraction_manifest.yaml
comsol_intake_summary.md
```

## Pass criteria

- All available input assets are classified.
- Coordinate system is known or explicitly marked unknown.
- The selected comparison mode is justified.
- Missing information is listed without guessing.

## Fail criteria

- Any downstream code is edited before model intake is complete.
- VIGUS-specific assumptions are used for a new COMSOL model.
- `.mph` access is assumed without checking local COMSOL/API availability.
