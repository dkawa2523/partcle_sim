## How changes cross the platform

Adding a model to an existing category changes its concrete catalog record,
field roles, equation owner, stage binding and the actual bound/applicability
proof family. Existing state, engine and persistence are reused when their
meaning is unchanged. A new force category also closes composition order and
proof coverage; it cannot silently become a zero force. Adding state requires
the explicit source/stage/dense/event/checkpoint/result vertical change.

Removing a model removes its selector, parameter/binding/proof branches and
dedicated callers/examples/explanations together. Other categories retain
their directly named shared primitives. Normal producers publish canonical
bundles through the existing publisher, and normal result consumers use the
same bound cohort and ResultView; neither introduces a second numerical path.
